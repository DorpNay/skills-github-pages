# aLandi — план реализации голосового помощника

**Срез:** 2026-10-28. Документ сводит уже существующие решения проекта; ссылки на upstream и записи в реестре кандидатов не означают, что runtime установлен или включён.

## Что уже есть в репозитории

- `index.md`: два UI-пути — голосовое сообщение с редактируемой транскрипцией и локальный half-duplex диалог; микрофон использует браузерный `MediaRecorder`, затем последовательность ASR → выбранный chat gateway → TTS.
- `gateway/app.py`: авторизованные локальные endpoints `POST /v1/audio/transcriptions` (whisper.cpp CLI), `POST /v1/audio/speech` (Piper CLI), `GET /v1/capabilities`; оба voice-флага выключены по умолчанию. ASR нормализуется через ffprobe/ffmpeg; временные файлы очищаются.
- `gateway/tests/test_audio_transcription.py`, `gateway/tests/test_audio_speech.py`, `tests/e2e/audio-transcription.spec.mjs`: покрывают контракт и пользовательский путь с fake subprocess/mock MediaRecorder/mock HTTP, но не качество настоящих моделей и не реальное оборудование.
- `evals/voice/language_matrix_v2.yaml`: кандидаты и лицензионные блокеры по языкам; SHA-256 весов/голосов пока не зафиксированы.
- `docs/MULTIMODAL_MODEL_STACK_RU.md`: рекомендует исследовать Qwen3-ASR-0.6B для RU/TH, Moonshine streaming для поддерживаемых языков и отдельно проверять каждый TTS voice. Это кандидаты, не автоматическая замена существующего whisper.cpp.
- `docs/LATENCY_CONTRACT.md`: определяет измерения first audible audio, endpoint delay, p50/p95, RTF и peak PSS; численные цели — ещё не результаты.
- `docs/V016_IMPLEMENTATION_CHECKLIST.md`: native audio frames, VAD/AEC, barge-in, voice lifecycle и language/license matrix остаются prototype/blocked/conditional.

## Upstream: что заимствовать

| Компонент | Источник из существующего реестра | Решение для aLandi |
|---|---|---|
| Базовый мультиязычный ASR | [whisper.cpp](https://github.com/ggerganov/whisper.cpp) | Оставить текущий локальный adapter для первого работающего цикла; он уже имеет bounded CLI contract. |
| Альтернативный RU/TH ASR | [Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR) | Benchmark позже против whisper.cpp по CER/WER, RTF, latency и RAM; не интегрировать до проверки точного checkpoint/hash/license. |
| Потоковый ASR на подходящих языках | [Moonshine](https://github.com/moonshine-ai/moonshine) | Отдельный эксперимент для streaming и браузерного/on-device пути; сначала подтвердить язык, размер WASM/runtime и лицензию конкретных voice assets. |
| Английский streaming | [ASR4ALL-S](https://huggingface.co/futo-org/asr4all-s) | Только английский; лицензия имеет специальные условия, не считать универсальным/коммерчески свободным. |
| TTS | [Piper](https://github.com/OHF-Voice/piper1-gpl) | Текущий локальный adapter сохраняется. Разрешать только предварительно установленные голоса; лицензия движка не заменяет проверку конкретной voice model. |
| VAD | [Silero VAD](https://github.com/snakers4/silero-vad) | Кандидат следующего этапа для определения конца реплики; не называть VAD эхоподавлением. |
| RU ASR fallback | [Vosk models](https://alphacephei.com/vosk/models) | Кандидат для сравнительного теста, не дополнительная зависимость первого релиза. |

## Реализация по этапам

1. **V1 — безопасный half-duplex:** закрепить выбор установленного TTS voice, список отдавать только через авторизованный `/v1/capabilities`; сервер принимает только allowlisted ID и проверяет наличие `.onnx` + `.onnx.json`. Не скачивать голоса автоматически и не отправлять аудио внешнему ASR.
2. **V1 acceptance:** gateway unit tests для выбора/отклонения голоса; E2E с двумя mock voice options; затем полный Gateway + Quality/Chromium/provenance CI.
3. **Реальный runtime:** оператор отдельно устанавливает whisper.cpp, ffprobe/ffmpeg, Piper и конкретные голосовые файлы; фиксирует версии, SHA-256 и лицензии. После этого включаются флаги на сервере и выполняются тесты с реальным микрофоном на целевом браузере.
4. **V2 — разговор в реальном времени:** потоковый ASR, VAD/end-of-turn, потоковый TTS и отмена/перебивание. До включения нужны аудиобуферы с лимитами, измерение self-echo/AEC, проверка гарнитуры/Bluetooth, lifecycle мобильного браузера и нагрузочные замеры.
5. **Выбор ASR:** только после baseline замеров сравнивать whisper.cpp, Qwen3-ASR, Moonshine или Vosk. Для каждого языка отдельно фиксировать WER/CER, холодный/тёплый запуск, RTF, p50/p95 и peak PSS. На 8 GB RAM не загружать несколько тяжёлых моделей одновременно.

## Критерии безопасности

- Голос и документы не включаются автоматически; нет скрытого fallback на стороннего провайдера.
- В API наружу возвращаются только ID/labels реально найденных локальных голосов; paths, secrets и содержимое файлов не выдаются.
- Неизвестный voice ID отклоняется, а не трактуется как путь.
- Аудио, транскрипт и временные файлы не попадают в обычные логи/долговременную память; Stop отменяет запрос и исключает позднее воспроизведение.
- Лицензия движка, модельных весов, voice pack и phonemizer проверяется отдельно. Пока exact SHA-256 и license review отсутствуют, соответствующий артефакт не считается готовым к поставке.

## Приземление на VPS — обязательная инструкция владельцу

**Что можно подготовить в репозитории:** код, параметры конфигурации, безопасные defaults, проверки и пошаговую инструкцию. **Что не доступно из GitHub-интеграции:** SSH-доступ к приватному VPS, установка системных пакетов или загрузка моделей непосредственно на сервер. Не передавайте сюда SSH-ключи, пароли, API keys, Tunnel tokens или содержимое production env-файлов.

### До установки моделей

1. Объединить PR с выбором Piper-голосов после зелёного exact-head CI; убедиться, что на VPS развёрнут именно этот commit, а не только опубликован GitHub Pages.
2. На VPS проверить ОС/архитектуру, свободный диск и RAM, текущие службы и bind addresses. На 8 GB RAM не держать одновременно несколько тяжёлых ASR/LLM/TTS моделей; начинать с одной модели Ollama и одного локального ASR/TTS процесса.
3. Установить системные зависимости, совместимые с ОС: Python 3.12+, ffmpeg (включая ffprobe), и собрать/установить whisper.cpp с whisper-cli. Не запускать команды установки до определения дистрибутива и архитектуры.
4. Проверить upstream-лицензию и точный источник/версию каждого артефакта. Для каждой модели записать URL источника, лицензию, версию и SHA-256 в реестр до включения функции. Лицензия движка не подтверждает лицензию весов/голоса.

### Установка локальных Piper voice packs

1. Установить Piper runtime в virtualenv сервиса; gateway вызывает его как `python -m piper`.
2. Создать закрытый каталог моделей, например `/var/lib/alandi-models/piper`, с правами только для сервисного пользователя.
3. Вручную загрузить только выбранные и лицензионно проверенные voice artifacts из подтверждённого upstream/release. Для каждого голоса нужны согласованные `.onnx` и `.onnx.json`. Не брать URL или SHA из непроверенных копий и не включать скачивание моделей из веб-запросов.
4. Сверить SHA-256 файлов с выбранным источником и записать лицензионные метаданные. Пока hash/license review не записаны, голос не считается готовым к поставке.
5. В `/etc/alandi-gateway.env` задать пути к бинарнику, каталогу и ID голосов. `ALANDI_AUDIO_SPEECH_VOICES` использует формат `voice-id=Label,another-id=Another label`; ID должны соответствовать установленным моделям. Права файла — `0600`; не отправлять его содержимое в чат.
6. Сначала оставить `ALANDI_AUDIO_SPEECH_ENABLED=false`; перезапустить gateway и проверить `/livez`, `/readyz` (Ollama) и авторизованный `/v1/capabilities`; `/healthz` остаётся совместимым alias readiness. Убедиться, что список содержит только реально установленные allowlisted голоса и не раскрывает пути. Затем включить флаг и перезапустить сервис.
7. Проверить синтез через авторизованный `POST /v1/audio/speech` с короткой несекретной фразой, проверить WAV и прослушать результат. Проверить выбор каждого голоса в мини-плеере и кнопку Stop/отмену.

### Установка локального whisper.cpp ASR

1. Получить binary/build whisper.cpp и модель из подтверждённого upstream; проверить архитектуру, лицензию и SHA-256. Не заменять текущую модель на Qwen3-ASR/Moonshine/Vosk без отдельного benchmark и интеграционного изменения.
2. Установить бинарник и модель в закрытые каталоги, доступные gateway-сервису; прописать абсолютные пути в `ALANDI_AUDIO_TRANSCRIPTION_BINARY` и `ALANDI_AUDIO_TRANSCRIPTION_MODEL`. Проверить доступность `ffprobe` и `ffmpeg`.
3. Сначала оставить `ALANDI_AUDIO_TRANSCRIPTION_ENABLED=false`, перезапустить сервис и проверить capabilities. Затем включить флаг и проверить запись через UI: транскрипт должен появиться в редактируемом composer и **не отправляться автоматически**.
4. Не отправлять пользовательское аудио сторонним ASR-сервисам. Проверить лимиты длительности/размера, timeout и очистку временных файлов.

### Сквозная проверка перед приземлением

1. Убедиться, что Ollama и gateway слушают только loopback; не публиковать порты `11434` и `8000` напрямую в интернет. Публичный маршрут — через настроенный Tunnel/Access с HTTPS и rate limiting.
2. Проверить `ALANDI_API_KEY`, CORS allowlist и выбранную модель в UI. Секреты задавать только на VPS и в локальных настройках пользователя. Не включать cross-provider fallback для приватного разговора.
3. Пройти сценарии: текстовый ответ → прочитать вслух → Stop → выбор голоса; запись → редактирование транскрипта → явная отправка → ответ в том же чате → воспроизведение. Проверять русский, английский и тайский только если выбранные модели действительно поддерживают эти языки.
4. Записать first-audio latency, полную задержку, ошибки, RAM/RSS, CPU и качество распознавания на целевом устройстве. Live streaming/barge-in не считать готовыми, пока отдельно не реализованы и не проверены потоковые аудиобуферы, VAD/end-of-turn, отмена и echo/AEC.
5. После изменения env проверить systemd service, журналы на отсутствие текста/аудио/секретов, перезапуск после reboot и rollback. Передавать только несекретные результаты: OS/архитектура, RAM/диск, health HTTP status, capability flags и доступные voice IDs, hash, задержки и пиковую RAM.

**Критерий приземления:** PR merged + exact-head CI зелёный + артефакты моделей с hash/license + gateway на VPS с флагами, включёнными осознанно + реальный микрофон/звук проверены + RAM/latency записаны. GitHub Pages deployment сам по себе не разворачивает приватный gateway и модели.
