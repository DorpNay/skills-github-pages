# Архитектура настроек запроса aLandi

**Статус:** принято к реализации в ветке `feat/chat-settings-orthogonal-controls-20261030`  
**Дата:** 2026-10-30  
**Область:** панель чата, меню функций, Search & Research Studio, семантика режимов выполнения.

## Цель

Оставить на поверхности минимальный набор понятных решений, сохранив расширенную управляемость. Каждая настройка должна менять ровно одно измерение запроса. Ни одна настройка не должна незаметно дублировать или переопределять эффект другой.

## Раунд 1. Семантическая инвентаризация

Проверка текущего `index.md` выявила четыре независимых измерения:

| Измерение | Текущее поле | Реальный эффект | Что оно не должно делать |
|---|---|---|---|
| Объём работы | `processingMode` (`fast` / `deep`) | Инструкция модели и бюджет циклов инструментов: быстрый режим — 1 раунд/1 вызов; тщательный — до 4 раундов, до 3 вызовов за раунд и до 8 вызовов за запуск | Не менять число результатов и набор источников веб-поиска |
| Доступ и ширина веб-поиска | `searchMode` (`offline` / `normal` / `more`) | Выключение веб-инструментов либо стандартный/расширенный охват результатов и открытых источников | Не увеличивать бюджет циклов выполнения |
| Способ выполнения | `multiAgentEnabled` | Разрешает структурированный конвейер «планировщик → исследователь → критик → синтезатор» для запросов, прошедших проверку сложности | Не обещать независимую команду моделей; не подменять профиль задачи |
| Профиль задачи | `skillPreset` | Добавляет специализированные инструкции для текущего чата | Не включать инструменты, веб-доступ или дополнительные разрешения |

Отдельно, вне этих четырёх измерений:

- **Контекст:** проект текущего чата, одноразовый контекст других проектов, вложения и разрешённые области памяти.
- **Модель и маршрут:** aLandi Cloud либо выбранный внешний провайдер/модель; это транспорт и исполнитель, а не режим задачи.
- **Формат ответа:** остаётся частью естественного запроса. Отдельный селектор «таблица/отчёт/код/кратко» не добавляется: он дублировал бы формулировку пользователя и профили задачи.

### Подтверждённые пересечения текущей реализации

До рефакторинга `searchMode === 'more'` и `processingMode === 'deep'` оба включали расширенный бюджет циклов инструментов. Кроме того, `processingMode === 'deep'` автоматически передавался в поисковые функции как расширенный режим результатов. Из-за этого:

- «Расширенный поиск» фактически менял и глубину выполнения;
- «Тщательно» меняло и ширину поиска;
- комбинация «Тщательно + Расширенный поиск» не давала независимого дополнительного эффекта по каждому измерению.

Search & Research Studio также содержала собственные селекторы глубины и веб-поиска, которые перезаписывали сохранённые настройки активного чата. Это второй интерфейс управления теми же полями.

## Раунд 2. Информационная архитектура

### Основная поверхность чата

Оставить на виду только два часто используемых решения:

1. **Объём работы:** Быстро / Тщательно.
2. **Веб-поиск:** Выключен / Обычный / Расширенный.

Остальные настройки находятся в меню «Функции»:

- **Структурированный разбор** — разрешение использовать существующий многоэтапный конвейер для сложных задач.
- **Профиль задачи** — инструкции планирования, исследования, код-ревью, анализа данных, систем агентов или мультимодальной обработки.
- **Коннекторы** — только фактически доступные интеграции; неподключённые не выдаются за работающие.

Research Studio остаётся отдельным пунктом боковой панели после списка чатов. Дублирующий пункт Research в меню «Функции» удаляется.

### Однострочная сводка

Под панелью показывается компактная сводка активного чата, например:

- `Быстро · Веб: обычный · Прямой разбор · Авто`
- `Тщательно · Веб: расширенный · Структурированный разбор · Исследование`

Названия профилей локализуются; внутренние значения вроде `code-review` пользователю не показываются.

### Research Studio

Studio — отдельное рабочее окно для составления исследовательского запроса, а не самостоятельный исполнительный режим.

- Использует настройки активного чата без их изменения.
- Показывает сводку этих настроек.
- Не имеет дублирующих переключателей глубины и веб-поиска.
- Чтобы изменить параметры, пользователь закрывает Studio и меняет их в основной панели.
- Само открытие/закрытие Studio не меняет сохранённые настройки чата.

## Раунд 3. Контракт поведения

1. `processingMode` управляет только инструкцией/бюджетом обработки.
2. `searchMode` управляет только доступом к веб-инструментам и шириной результатов поиска.
3. `multiAgentEnabled` управляет только разрешением структурированного конвейера; фактический запуск остаётся ограничен проверкой сложности.
4. `skillPreset` меняет только инструкции. Профиль `auto` сохраняет лёгкий путь для быстрых запросов; для сложных/тщательных запросов профиль выбирается автоматически, если это поддерживает текущий классификатор.
5. Настройки остаются per-chat и продолжают экспортироваться/импортироваться вместе с чатом.
6. Новый чат начинает с безопасных компактных значений: Быстро, обычный веб-поиск, прямое выполнение, профиль Авто.
7. `offline` означает «веб-инструменты выключены», а не «всё приложение работает без интернета»: облачному API всё ещё может требоваться сеть.

## Раунд 4. Проверка комбинаций

| Объём работы | Веб-поиск | Способ выполнения | Ожидаемое поведение |
|---|---|---|---|
| Быстро | Обычный | Прямой | 1 раунд инструментов; стандартный набор результатов |
| Быстро | Расширенный | Прямой | 1 раунд инструментов; больше результатов/источников в поисковом вызове |
| Тщательно | Обычный | Прямой | До 4 раундов/8 вызовов; стандартный охват результатов |
| Тщательно | Расширенный | Структурированный | Расширенный бюджет обработки и расширенный охват поиска; конвейер только для сложных запросов |
| Тщательно | Выключен | Прямой/структурированный | Нет веб-инструментов; работа только с сообщением, вложениями и разрешённым контекстом |

Профиль задачи может сочетаться с любой строкой таблицы: он меняет инструкции, а не бюджет и разрешения.

## Раунд 5. Критерии приёмки

- [ ] Расширенный веб-поиск не увеличивает число раундов/вызовов инструментов.
- [ ] Тщательный режим не расширяет число результатов веб-поиска сам по себе.
- [ ] Offline не предлагает веб-инструменты даже в тщательном/структурированном режиме.
- [ ] Смена профиля не включает веб-поиск и не включает структурированный конвейер.
- [ ] Структурированный разбор не называется «командой независимых агентов».
- [ ] Research Studio не меняет настройки чата и показывает их текущую сводку.
- [ ] Настройки сохраняются отдельно для каждого чата; импорт/экспорт не теряет значения.
- [ ] Русские и английские подписи и подсказки согласованы.
- [ ] На мобильном экране базовые контролы остаются читаемыми и доступны для касания.

## Внешние ориентиры

- [Open WebUI](https://github.com/open-webui/open-webui) — разделение настроек модели, аккаунта и чата.
- [LibreChat](https://github.com/LibreChat-AI/LibreChat) — группировка общих настроек, поведения чата, речи и приватности.
- [Apple Human Interface Guidelines: Layout](https://developer.apple.com/design/human-interface-guidelines/layout/) — постепенное раскрытие сложности.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) — доступность, размеры целей и видимость фокуса.

Чужой код не переносится напрямую: aLandi сохраняет статическую архитектуру и существующую модель состояния.
