# aLandi — аудит готовности голосового помощника и документов

**Дата аудита:** 2026-10-28  
**Основа:** текущие документы и кодовые контракты в `main`; не является доказательством работы VPS или реального оборудования.  
**Цель:** довести существующие функции до проверяемого пользовательского сценария, не создавать параллельные реализации и не включать рискованные функции автоматически.

## Краткий вердикт

- **Голосовой ввод:** UI и путь записи → локальный ASR endpoint → редактируемая расшифровка покрыты E2E с mock MediaRecorder и mock gateway. Реальный микрофон, совместимость кодеков, whisper.cpp и модель на целевом устройстве не подтверждены.
- **Озвучивание ответа:** UI-кнопка, локальный TTS endpoint и mini-player существуют; E2E использует mock WAV. Реальная установка Piper, совместимость голоса, воспроизведение на iOS и задержка не подтверждены.
- **Диалог голосом:** PR #60 добавил прототип half-duplex цикла. Это не непрерывный streaming voice: VAD, streaming ASR, barge-in/перебивание, управление очередью TTS, маршрутизация аудио и echo cancellation остаются отдельными задачами.
- **Документы:** gateway extraction contract поддерживает PDF (до 40 страниц), DOCX, XLSX (до 20 листов), TXT, Markdown, CSV и JSON. Endpoint выключен по умолчанию. Сканированные PDF без текстового слоя не поддерживаются без OCR.
- **Подключение UI документов:** E2E подтверждает, что PDF из attachment flow отправляется на настроенный aLandi gateway, а извлечённый текст добавляется в запрос как недоверенные справочные данные. Это тест с подменёнными ответами, не реальный end-to-end запуск.
- **Инфраструктура:** gateway, Ollama, ASR/TTS runtime, модели и Cloudflare Tunnel на VPS не подтверждены как совместно работающие.

## Принципы реализации

1. Не называть mock E2E доказательством реального микрофона, модели, синтеза речи или сервера.
2. Голос и бинарное извлечение остаются выключенными, пока оператор явно не установил runtime, проверил лицензии/хэши артефактов и включил флаги.
3. Исходные аудио/документы не должны незаметно попадать в долговременную память, логи или response cache. Передавать только по явному действию пользователя; извлечение/аудио ответы должны иметь `Cache-Control: no-store`.
4. Расшифровка до отправки остаётся редактируемой. Запись и TTS должны иметь доступный Stop/Cancel, который отменяет активный запрос и не позволяет устаревшему ответу запустить воспроизведение.
5. Текст документа/транскрипта — недоверенное содержимое, а не инструкции системе. Сохранять происхождение источника; не исполнять инструкции из вложений.
6. Не обещать OCR, распознавание видео-аудио, Google Drive sync, real-time streaming или многопользовательскую безопасность без соответствующего runtime и тестов.
7. На личном статическом клиенте API key в браузерном хранилище — только прототип для одного владельца; это не серверная multi-user авторизация.

## Этапы приёмки голосовой функции

### V0 — Контракт и безопасность
- [ ] `GET /v1/capabilities` отражает только реально включённые функции.
- [ ] Неавторизованные запросы получают 401; тело, длительность и время выполнения ограничены.
- [ ] Конкурентные ASR/TTS задачи не копятся бесконечной очередью; корректно возвращается 429.
- [ ] Временные аудиофайлы удаляются при успехе и ошибке; сырой звук не пишется в логи и долговременную память.
- [ ] Проверены лицензии и SHA-256 бинарника/моделей/голоса; runtime пути задаются оператором, ничего не скачивается автоматически.

### V1 — Реальный локальный ASR
- [ ] Установлены совместимые `whisper.cpp`, `ffprobe` и локальная ASR-модель.
- [ ] На целевом устройстве браузер действительно получает микрофонное разрешение, записывает поддерживаемый MIME/кодек и корректно останавливает треки.
- [ ] Русская, английская и тайская короткие записи проходят через настоящий endpoint; ошибки формата/пустой записи объясняются пользователю.
- [ ] Транскрипт вставляется в composer и остаётся редактируемым; автоматической отправки нет.
- [ ] Измерены время до первой расшифровки, длительность аудио, пиковая RAM и точность на фиксированном небольшом тестовом наборе.

### V2 — Реальный локальный TTS
- [ ] Установлены совместимые Piper runtime и voice model с проверенной лицензией.
- [ ] Несколько ответов на русском/английском синтезируются в валидный WAV и воспроизводятся на целевом iPhone/браузере.
- [ ] Stop отменяет запрос и воспроизведение; повторное нажатие не запускает дубликат.
- [ ] Измерены latency, длительность генерации, размер WAV и RAM.
- [ ] Синтез отключён при недоступном runtime, без имитации успешного ответа.

### V3 — Half-duplex голосовой помощник
- [ ] Один цикл: запись → остановка → ASR → редактируемый/подтверждённый текст → обычный запрос выбранному провайдеру → TTS → воспроизведение → следующий ход.
- [ ] Нет автоматической отправки до подтверждённого состояния, если режим явно не настроен на это.
- [ ] Ошибка на любом этапе оставляет пользователя в восстанавливаемом состоянии; нет скрытой повторной записи или позднего воспроизведения.
- [ ] Отдельно проверены iOS Safari, блокировка/разблокировка экрана, переключение аудиоустройства и прерывание звонком.
- [ ] Только после измерений решить, нужен ли streaming/VAD/barge-in; не добавлять их как фиктивную настройку.

## Этапы приёмки документов

### D0 — Защищённое извлечение
- [ ] Проверить `ALANDI_DOCUMENT_EXTRACTION_ENABLED=false` по умолчанию; включать только на намеренно настроенном gateway.
- [ ] Проверить реальные сигнатуры/MIME, расширения, пределы размера, страниц/листов, ZIP entries, коэффициента сжатия, времени и длины извлечённого текста.
- [ ] Проверить повреждённые файлы, архивную бомбу, неверное расширение, пустой/сканированный PDF, превышение лимитов и cleanup временных данных.
- [ ] Сохранить `no-store`; не отправлять документ в стороннего провайдера без явного выбора и применимых настроек согласия/приватности.

### D1 — Путь от вложения до ответа модели
- [ ] На реальном gateway вложить по одному TXT, PDF с текстовым слоем, DOCX, XLSX, CSV и JSON.
- [ ] Подтвердить, что извлечённое содержимое действительно включено в prompt активного провайдера, а не просто отображено в UI.
- [ ] Проверить страницы/листы и происхождение источника; для таблиц не терять заголовки, порядок и значения ячеек.
- [ ] Недоступный parser или превышение лимита блокирует отправку с понятной ошибкой, а не создаёт впечатление, что модель прочитала файл.
- [ ] Проверить раздельные сценарии собственного и стороннего провайдера: документ не должен незаметно менять выбранный маршрут.

### D2 — Следующий уровень ingestion (не считать реализованным)
- [ ] OCR для сканированных PDF и изображений — отдельный локальный компонент, лицензия, лимиты и тесты.
- [ ] Chunking с page/offset/source hash, preview и подтверждением перед индексацией.
- [ ] Re-index/delete, удаление производных chunks вместе с источником, provenance и тесты scope isolation.
- [ ] XLSX: отдельно определить формулы, отображаемые значения, листы и лимиты.
- [ ] Видео: выборка кадров не равна расшифровке звука; audio track, ASR и синхронизация требуют отдельного pipeline.
- [ ] Google Drive OAuth/Picker/sync не обещать до завершения UI, encrypted token storage, revoke и проверки удаления индекса.

## Release gate

Не объявлять «голос работает» или «документы полностью поддерживаются», пока не выполнены соответствующие реальные проверки на целевом устройстве и развернутом gateway. Для каждой функции фиксировать: commit SHA, версии runtime и модели, SHA-256 артефактов, feature flags, устройство/ОС, точные команды, результат тестов, latency/RAM, известные ограничения и rollback.
