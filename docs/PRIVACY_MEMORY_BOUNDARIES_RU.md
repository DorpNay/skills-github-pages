# Границы памяти и приватности aLandi

**Проверка кода:** 2026-10-28. Этот документ разделяет подтверждённую реализацию, новое изменение в PR и незакрытые требования. Наличие кода в ветке не означает, что он уже опубликован или включён на VPS.

## Модель данных

| Контур | Хранилище | Допускается в сторонний провайдер? | Как попасть туда |
|---|---|---|---|
| Личная память локальной модели | IndexedDB `memory` в браузере | **Нет** | Ручное добавление или явная команда `Запомни: …`; контекст только через маршрут `alandi` |
| Общая память | Отдельный IndexedDB store `sharedMemory` | Только если пользователь включил использование общей памяти для запроса | Ручное добавление, команда `Сохрани в общую память: …`, либо отдельное подтверждение при переносе одного личного факта |
| Память проекта в клиенте | Проектные данные в браузере | Может попасть в контекст выбранного провайдера, когда проект прикреплён к запросу | Явно прикрепить/выбрать проект; область `project-only` или `project-and-global` ограничивает общие заметки |
| Серверная графовая память | SQLite на собственном gateway | Не отправляется напрямую внешнему LLM автоматически; факт, выбранный в контекст локального запроса, остаётся в запросе gateway | Включённый флаг, отдельное согласие чата, только подтверждённые факты; ручной перенос |
| История чата | IndexedDB/localStorage браузера | История отправляется выбранному провайдеру в пределах контекста запроса | Пользователь отправляет сообщение; при смене провайдера история обычно остаётся в чате |

**Общая память означает «общая для разрешённых маршрутов в этом браузере», а не облачную синхронизацию между устройствами.** Перенос в общую память не удаляет исходную личную копию. В браузере нет защиты от пользователя с полным доступом к профилю, расширений с широкими разрешениями или XSS; IndexedDB — граница приложения, не аппаратное шифрованное хранилище.

## Изменения в ветке `feat/privacy-scoped-memory-20261028`

1. IndexedDB повышена с версии 1 до 2. Существующий store `memory` сохраняется как личная память; добавляется отдельный `sharedMemory`. Старые заметки **не** копируются автоматически в общую память.
2. В UI личные и общие заметки отображаются отдельно. Перенос одного личного факта требует подтверждения; личная копия остаётся на месте.
3. Общие заметки попадают в контекст только при включённом `ai_global_memory_enabled_v1` и разрешающей области проекта.
4. Личные заметки подбираются только при выбранном провайдере `alandi`, ограничены четырьмя фактами/1200 символами и помечаются отдельными границами в системном контексте.
5. Если личный факт реально вошёл в prompt, чат помечается `privateMemoryUsed`. Этот чат нельзя отправить внешнему провайдеру; нужно вернуться к `alandi` или создать новый чат. Это защищает и историю, где ответ модели мог отразить личный факт.
6. Дополнительный предохранитель фильтрует кандидатов маршрута: запрос с маркером личной памяти может уйти только кандидату `alandi`, даже если включён межпровайдерный fallback.
7. Явные команды `Запомни: …` и `Сохрани в общую память: …` обрабатываются до сетевого запроса. Команда личной памяти работает только на `alandi`; команда общей памяти требует подтверждения. Команды не отправляются LLM как обычный prompt.

## Ограничения текущего этапа

- Это клиентское хранилище в том же браузерном профиле; отдельные физические файлы/ключи/профили IndexedDB для разных моделей не создаются. Изоляция достигается раздельными stores и проверкой маршрута.
- Серверная память и клиентская IndexedDB пока не образуют одну синхронизируемую систему. Не считать автоматическую синхронизацию включённой.
- Автоматическое извлечение долговременных фактов из произвольного разговора **не включено**. Запись происходит вручную или после явной команды пользователя. Это преднамеренно: авто-сохранение без проверки может записать секреты, случайные высказывания или prompt injection.
- Личные факты не добавляются к запросам внешнего провайдера. Однако пользовательские сообщения и обычная история чата всё равно отправляются выбранному провайдеру при обычной работе; этот контур не является локальным архивом всего диалога.
- Проекты и прикреплённые к запросу данные — отдельный контур. Они не объявляются приватными только из-за того, что личная память защищена.
- Ветка ещё должна пройти точный CI, включая HTML/JS integrity sentinel, security/context sentinels, Jekyll build и Chromium E2E. Нельзя считать это изменение уже на production.

## Проверка перед merge

1. Запустить Quality Sentinels на точном head и проверить, что новые статические контракты проходят.
2. В Chromium проверить: upgrade IndexedDB v1→v2 сохраняет старые личные заметки; shared store создаётся пустым; перенос выбранного факта требует подтверждения; удалить можно независимо.
3. Перехватить сетевые запросы при включённом cross-provider fallback: при prompt с личным маркером не должно быть ни одного запроса к стороннему домену.
4. Проверить блокировку отправки истории чата внешнему провайдеру после использования личной памяти, включая перезагрузку страницы.
5. Проверить команду `Запомни: …` без API-ключа: факт сохраняется локально, а сетевой запрос не выполняется. Для общей памяти проверить отдельное подтверждение.
6. Проверить переключатель общей памяти и `project-only`/ `project-and-global` на трёх случаях: без проекта, проект-only, проект-and-global.
7. Провести ручной тест с настоящим внешним провайдером только на синтетических заметках, без личных данных.

## Решение по автосохранению

Не сохранять факты автоматически из каждого диалога по умолчанию. Следующий безопасный этап — опциональный сбор **кандидатов** в отдельный список, локальная проверка чувствительных данных и подтверждение пользователя перед переносом в общую память. Пока этот цикл не реализован и не протестирован, не описывать память как самонаполняющуюся без ограничений.
