# Аудит памяти aLandi: сохранность, архив, источники и синхронизация

Дата аудита: 2026-10-27. Это проектное решение/план, а не заявление о готовой функции.

## Вывод

Сейчас нельзя честно обещать «потерь не будет»: клиентская история в браузерном хранилище уязвима к очистке данных сайта, ограничениям квоты, повреждению и потере устройства. Есть экспорт истории/проекта и восстановительная копия, но их наличие само по себе не гарантирует, что пользователь регулярно экспортирует данные, что копия независима от исходного хранилища или что восстановление проверено. Gateway memory sync и graph — отдельные опциональные прототипы, не завершённая единая синхронизация.

## Что уже есть в коде

- `index.md`: `safeSet` для localStorage, recovery backup, экспорт чатов и проектов, IndexedDB для части данных.
- `gateway/memory/delta_sync.py`: версионированные ограниченные JSON Patch-дельты для состояния разговора, checksum и обнаружение конфликтов; не покрывает автоматически profile/project/global scopes.
- `gateway/memory/manager.py` + `schema.sql`: SQLite memory graph с scope, provenance, временными полями, статусами candidate/confirmed/disputed/superseded/rejected и FTS5.
- Gateway endpoints выключены feature flags по умолчанию. OAuth/Google Drive groundwork не означает настроенный Drive Picker или рабочий двусторонний sync.
- Точные лимиты браузерной квоты зависят от браузера/устройства; фиксированный размер нельзя гарантировать для всех.

## Принципы, которые нужно внедрить

1. **Источник прежде сводки.** История диалога, аудио, исходный файл и транскрипт — самостоятельные источники. Сводка не заменяет и не удаляет источник.
2. **Append-only версии.** Для длинного голосового разговора новые сегменты/события добавляются с монотонным sequence ID и source ID; редактирование — новая версия/дельта с указанием предыдущей версии, а не молчаливое перезаписывание.
3. **Идемпотентность и целостность.** У каждого объекта: stable ID, SHA-256, размер, тип, created/updated timestamps, scope, origin, revision. Повторная доставка одного ID не создаёт дубликаты; одинаковые ID с разным hash дают конфликт, а не overwrite.
4. **Две независимые копии для важных данных.** Локальный оригинал + экспорт/backup в выбранное пользователем место. Если включён собственный gateway — третья копия только по явному согласию. Одна папка/один диск не считается резервированием от отказа устройства.
5. **Предупреждение заранее.** Перед записью измерять доступную квоту через `navigator.storage.estimate()` и, если поддерживается, запрашивать persistent storage; показывать предупреждение по порогам 70/85/95% от доступной квоты, а при QuotaExceededError блокировать рискованную перезапись, предлагать экспорт и повтор. Числа — предлагаемые пороги, подлежат UX/eval.
6. **Экспорт с проверкой.** Версионированный bundle с manifest, hash каждого файла, чатов, вложений и памяти; экспорт должен включать фактические байты всех вложений, если пользователь выбрал полный backup. Проверять импорт, целостность, количество объектов и конфликты до замены. Предпочитать merge/restore в новый профиль, а не перезапись.
7. **Компактная память — отдельный слой.** Сжимать архивы/старые сообщения после сохранения оригинала; извлекать структурированную сводку с ссылками на исходные сообщения/временные метки и транскрипты. Сжатие не удаляет семантические данные и не должно происходить без контроля качества.
8. **Конфликты видимы.** При синхронизации использовать revision/base revision, content hash и append-only журнал. При конфликте — сохранить обе версии и запросить решение; не применять last-write-wins к памяти без явной политики.
9. **Ясная модель scope.** Conversation, project, user/global и source vault — разные пространства. Нельзя автоматически превращать приватный документ в global memory или включать чужие project facts.
10. **Безопасность.** Локальное шифрование полезно для чувствительных данных, но ключ не должен храниться рядом с ciphertext без защиты. Для синхронизации TLS + auth, at-rest encryption на сервере, экспорт шифровать опционально. Компрессия перед шифрованием.
11. **Вложения из пути — не универсально.** Обычный веб-клиент не может произвольно читать `/path/to/file` после перезапуска/в другом устройстве. При выборе файла можно хранить FileSystemHandle, если браузер поддерживает File System Access API и пользователь дал разрешение; разрешение может истечь, файл переехать или измениться. Нужны повторная проверка permission + size/mtime/hash, кнопка «обновить источник» и fallback на копирование/загрузку. Нельзя считать один путь устойчивым идентификатором.
12. **Источники без копирования.** В пределах одного браузерного профиля handle/URI может ссылаться на оригинал; для portable проекта нужно явно выбирать: ссылка-only (хрупко), копия в локальном source vault (надёжнее) или импорт на gateway. При отсутствии доступа — пометка «источник недоступен», не тихая потеря.

## Предлагаемый конвейер

`Capture -> Immutable source vault -> Hash/metadata -> Transcript/extraction -> Versioned derived artifacts -> Compact summaries with provenance -> Scoped retrieval -> Backup/sync`

Для audio: сегменты транскрипции append-only; raw audio хранится только если пользователь разрешил и есть место; если не хранится — это надо сообщить, потому что текст не восстанавливает голос оригинала.

## Этапы реализации (по убыванию приоритета)

### P0 — сейчас
- Сделать единый экспорт полного профиля с manifest/hash, включающим историю, проекты, memory, настройки (секреты по умолчанию исключены), и прикреплённые байты при выбранном full-backup режиме.
- Проверить/починить импорт: validate schema + sizes + hashes; preview/dry-run; никогда не очищать старое до успешного восстановления.
- Добавить UI-индикатор storage usage, quota estimate, предупреждения и явный «Экспортировать резервную копию».
- Проверить все save paths: QuotaExceededError, IndexedDB transaction abort, corrupted JSON, crash mid-write; не затирать последнюю валидную копию пустым/невалидным состоянием.
- Проверить длинную сессию: 1000+ сообщений/аудиосегментов, повторное подключение, duplicate delivery, reload и export/restore.

### P1 — единый локальный архив
- Добавить versioned append-only event log/SQLite vault для источников и derived artifacts с хешами и ссылками.
- Использовать chunked blobs, а не хранить большие аудиофайлы/base64 в localStorage; localStorage оставить для небольших настроек/индексов.
- Компактировать только старые производные данные; оригиналы неизменяемы, retention policy явная.
- Сделать автоматический локальный checkpoint после N сообщений/по времени и перед рискованными миграциями, с bounded count и контролируемым удалением только после проверки новой копии.

### P2 — подключаемые хранилища
- Ввести StorageProvider contract: `list/read/write/delete/version/health/estimate`, capabilities, auth scope и retry/backoff.
- Local IndexedDB/OPFS — основной автономный provider; gateway sync — опциональная копия; Google Drive/другой connector — опциональный provider после реального OAuth, с явной настройкой направления sync.
- Не запускать две стороны синхронизации одновременно без revision protocol. По умолчанию «local-first + manual backup»; автоматическая двусторонняя синхронизация только после conflict tests.
- Дать пользователю выбрать «только локально», «локально + мой gateway», «локально + облако», показывать последнее успешное резервирование и число несинхронизированных объектов.

### P3 — интеллектуальная память
- Сохранять сводки с provenance: source IDs, message ranges/timecodes, model/version, summary hash.
- Проверять summary against source (coverage/contradictions); если не уверены — оставить original, не сжимать.
- Retrieval scoped и source-aware; удаление/исправление должно распространяться через tombstones и revision log на все подключённые копии.

## Условия приёмки

- Нет тихого удаления/перезаписи при quota, malformed state или sync conflict.
- Экспорт можно импортировать в чистый профиль; hashes/количество объектов совпадают.
- Тесты подтверждают восстановление после сбоя посередине записи и дубликатной доставки.
- Длинный чат не заменяет старые факты новой сводкой без ссылки и версии.
- Отказ Google Drive/gateway не блокирует локальную работу; отсутствие интеграции не изображается как sync.
- При 85% квоты появляется понятное предупреждение и экспорт; при 95%/QuotaExceeded запись не уничтожает старую копию.
- Проверены права на файлы и восстановление FileSystemHandle после reload, включая недоступный/перемещённый оригинал.

## Решение

Не вводить новую базу/сервис только ради моды. Сначала укрепить уже существующие localStorage/IndexedDB export paths, измерения квоты, атомарность и restore tests. Затем source vault с content-addressed blobs. Google Drive подключать лишь после проверки реального OAuth и конфликтного sync. Это даст автономность без ложного обещания «память бесконечна».
