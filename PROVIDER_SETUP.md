# Настройка провайдеров AI Mobile Agent

Инструкция к приложению GitHub Pages: <https://dorpnay.github.io/skills-github-pages/>.

**Не присылайте реальные API-ключи в чат, issue или pull request.** Большинство ключей, введённых в настройки приложения, хранится в локальном хранилище браузера. Для более сильной защиты секретов нужен серверный прокси.

## Pollinations.ai — подключение браузера через OAuth PKCE

1. Откройте [официальную документацию Pollinations](https://gen.pollinations.ai/docs) и страницу [App Keys](https://enter.pollinations.ai/keys).
2. Создайте **App Key**. В поле приложения вставляется публичный ключ с префиксом `pk_`. Не вставляйте вместо него секретный `sk_` ключ.
3. В настройках App Key зарегистрируйте Redirect URI **в точности**:
   `https://dorpnay.github.io/skills-github-pages/`
   Схема HTTPS и завершающий слэш имеют значение. Redirect URI должен совпасть с адресом, на который вернётся пользователь после согласия.
4. В AI Mobile Agent откройте настройки → выберите **Pollinations.ai** → вставьте App Key → нажмите **«Подключить аккаунт Pollinations · PKCE»**. Этот шаг сохраняет App Key и начинает OAuth.
5. Подтвердите доступ в Pollinations и дождитесь возврата в приложение. После этого временный access token будет храниться только в `sessionStorage` текущей вкладки. В `localStorage`, URL и журнал он не записывается.
6. Нажмите **«Проверить соединение и модель»**. Если тест прошёл, лампа загорится зелёным; теперь можно отправлять сообщения.

Приложение просит доступ только к текстовым моделям (`models=text`), с бюджетом **5 Pollen** и сроком **7 дней**. Проверьте значения на экране согласия. Pollinations расходует Pollen согласно модели, бюджету и вашему аккаунту; не следует считать его безлимитным бесплатным API.

Если OAuth не завершается, проверьте точное совпадение Redirect URI в App Key. Ключ с префиксом `pk_` используется как `client_id`; временный `sk_` токен выдаётся только после согласия. После закрытия вкладки сессию может понадобиться подключить заново.

Для серверного smoke-test в GitHub Actions используется отдельный секрет `POLLINATIONS_API_KEY` со значением `sk_…`. Не используйте этот секретный ключ в браузерном поле.

Официальные инструкции: [API docs](https://gen.pollinations.ai/docs), [OAuth/Connect User Wallets](https://github.com/pollinations/pollinations/blob/main/BRING_YOUR_OWN_POLLEN.md).

## Hugging Face Inference Providers

1. Создайте токен в [Hugging Face Token Settings](https://huggingface.co/settings/tokens).
2. Выберите **fine-grained token** и включите право **Make calls to Inference Providers**.
3. В настройках приложения выберите **Hugging Face Inference Providers**, вставьте токен и сохраните настройки.
4. Кнопка **«Обновить все»** синхронизирует каталоги всех провайдеров с сохранёнными ключами — это нужно не только для выпадающего списка, но и для межпровайдерного резерва. На старте приложение автоматически обновляет активный каталог; если включён резерв у других провайдеров, устаревшие каталоги подключённых провайдеров также обновляются фоново. Списки кэшируются до 6 часов.
5. По умолчанию выбирается `openai/gpt-oss-120b:fastest`. Также доступны модели `deepseek-ai/DeepSeek-R1:fastest` и `openai/gpt-oss-120b:cheapest`. Правило `:fastest` выбирает наиболее быстрый доступный маршрут, а `:cheapest` — наиболее экономичный на стороне HF.
5. Нажмите **«Проверить соединение и модель»**.

Base URL: `https://router.huggingface.co/v1`. Полный запрос идёт на `/chat/completions`.

Типовые ошибки: 401/403 — токен, его разрешения или доступ к аккаунту; 402/429 — оплата, квота или лимит; 404 — неверный/недоступный ID модели. Цена и доступность могут отличаться у разных провайдеров HF.

Официальная документация: [Inference Providers](https://huggingface.co/docs/inference-providers/en/index), [Token settings](https://huggingface.co/settings/tokens).

## Groq Cloud

1. Создайте API key в [Groq Console](https://console.groq.com/keys).
2. В настройках выберите **Groq**, вставьте ключ и сохраните.
3. Начальная модель — `openai/gpt-oss-120b`; альтернативы — `qwen/qwen3.8-27b` и `openai/gpt-oss-20b`.

Предложенные старые ID `llama3-8b-8192` и `mixtral-8x7b-32768` не включены в актуальный список приложения: они относятся к прежнему каталогу Groq и не подходят как надёжный default для новой интеграции. Бесплатный доступ и скорость зависят от текущих лимитов аккаунта; высокая скорость не означает неограниченный бесплатный доступ.

Официальные страницы: [Models](https://console.groq.com/docs/models), [Deprecations](https://console.groq.com/docs/deprecations), [Rate limits](https://console.groq.com/docs/rate-limits).

## xAI / Grok

1. Создайте ключ в [xAI Console](https://console.x.ai/).
2. Выберите **xAI · Grok**, вставьте ключ и сохраните.
3. Base URL: `https://api.x.ai/v1`; модель по умолчанию — `grok-4.7`.

**xAI и Groq — разные провайдеры.** Ключ Groq не работает в API xAI, и наоборот.

Официальная документация: [xAI API Reference](https://docs.x.ai/developers/rest-api-reference/inference).

## Cloudflare Workers AI

1. В Cloudflare Dashboard найдите **Account ID** нужного аккаунта.
2. Рекомендуемый путь: на странице **Workers AI** выберите **Use REST API → Create a Workers AI API Token** и сохраните созданный токен. Если создаёте токен вручную, Cloudflare указывает разрешения уровня аккаунта **Workers AI Read** и **Workers AI Edit**. Не путайте их с разрешениями AI Gateway — это другой продукт.
3. В AI Mobile Agent выберите **Cloudflare Workers AI** и заполните поле Account ID — ровно 32 шестнадцатеричных символа.
4. Вставьте API Token в поле API Key и сохраните. Приложение само сформирует Base URL:
   `https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/ai/v1`
5. Нажмите **«Проверить соединение и модель»**. Модель по умолчанию — `@cf/openai/gpt-oss-120b`; доступны также `@cf/openai/gpt-oss-20b` и `@cf/meta/llama-3.3-70b-instruct-fp8-fast`.

Интеграция использует OpenAI-совместимый endpoint `/ai/v1/chat/completions`. Путь `/ai/run/<model_name>`, приведённый в вопросе, — отдельный нативный REST API с другим форматом тела запроса. Для текущего общего маршрутизатора выбран совместимый API; не добавляйте `/chat/completions` в Base URL вручную.

Использование Workers AI может расходовать лимиты/платные единицы Cloudflare — бесплатность не гарантируется.

Официальная документация: [OpenAI-compatible endpoints](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/), [GPT-OSS 120B](https://developers.cloudflare.com/workers-ai/models/gpt-oss-120b/), [Models](https://developers.cloudflare.com/workers-ai/models/).

## Актуальный каталог моделей и авто-переключение

В настройках есть поиск по ID/названию и кнопка **«Обновить все»**. Она обновляет каталоги провайдеров, для которых в текущем браузере сохранён ключ или доступна Pollinations-сессия; максимум два каталога запрашиваются параллельно. При запуске автоматически обновляется только выбранный провайдер, если межпровайдерный резерв выключен. Если включён **«Разрешить резерв у другого провайдера»**, подключённые провайдеры тоже обновляются фоново.

Каталоги получаются через API самих поставщиков: Google/Groq/NVIDIA/Hugging Face — OpenAI-совместимый endpoint моделей, xAI — список языковых моделей, OpenRouter — список текстовых моделей с сортировкой по популярности, Pollinations — отдельный публичный текстовый каталог, Cloudflare — официальный поиск Workers AI по задаче `text-generation`. Перед показом отсекаются очевидные embedding, image/audio, reranking, moderation и подобные записи. Если API не поддерживает каталог, заблокирован CORS или запрос отклонён, остаются встроенные варианты и ручной ввод модели.

Для быстрой работы на мобильном устройстве сохраняется максимум 250 моделей на провайдера; свежесть кэша — 6 часов. Кэш содержит ID и ограниченные поля описания, время получения и односторонний SHA-256 fingerprint ключа — не сам ключ и не ответ модели. Изменение ключа или endpoint помечает каталог устаревшим. Старый список можно просмотреть вручную, но устаревшие динамические записи не используются для автоматического резерва. Если сохранённый ID больше не встречается в каталоге, приложение всё равно показывает остальные модели и позволяет оставить прежний ID вручную.

Наличие модели в каталоге **не гарантирует**, что конкретная модель разрешена вашему аккаунту, квоте или платному плану. Автопереключение ограничено небольшим количеством кандидатов: сначала выбранная модель, затем до 7 дополнительных моделей того же провайдера; весь маршрутизатор ограничен 16 попытками. Другой провайдер рассматривается только если вы явно включили резерв между провайдерами. Другой ID модели пробуется лишь при распознанной model-specific ошибке 400/404; ошибки ключа, квоты/429, сети и сервера не превращаются в слепой перебор.

GitHub Actions Secrets — это секреты **серверной CI-среды**, они не доступны статическому сайту GitHub Pages. Каталог в браузере запрашивается с ключом, введённым в настройках приложения; Pollinations использует публичный каталог и отдельный OAuth PKCE для генерации. Workflow smoke-test поддерживает стандартные имена Actions Secrets и популярные aliases (например, `GEMINI`, `GROQ`, `GROK`, `OPENROUTER`, `NVIDIA`, `HUGGINGFACE`, `CLOUDFLARE`). Значения секретов не печатаются в журналах.

## Перенос настроек и журнал исследования

Кнопки **«Скачать профиль настроек»** и **«Импорт профиля»** переносят выбранного провайдера, модель, Base URL, режимы и системный промпт в JSON-файле. Профиль намеренно **не содержит API-ключи, Tavily-ключ и OAuth-токены**; импорт не заменяет секреты, которые уже сохранены в браузере. После импорта выбранный провайдер может потребовать повторной проверки модели.

Журнал исследования можно скачать как Markdown для чтения или как JSON для последующей обработки/сравнения. В новых журналах сохраняются настройки запуска (режим, наличие веб-поиска и межпровайдерного резерва), время начала и длительность, односторонний fingerprint настроенного системного промпта и история успешных/неудачных попыток маршрутизации с HTTP-статусами, безопасными категориями ошибок и длительностью. Также сохраняется размер эффективного системного промпта исследовательского pipeline в символах и до 40 уникальных источников, которые действительно вернули веб-инструменты: публичная HTTPS-ссылка, заголовок, имя источника/инструмента и короткий фрагмент. Перед отображением и экспортом ссылка проверяется повторно. Это список найденных источников, а не автоматическое доказательство, что каждое утверждение ответа опирается на конкретную ссылку. Сам текст системного промпта, API-ключи и содержимое заголовков Authorization в телеметрию не копируются. Старые журналы остаются открываемыми и экспортируются без новых полей. Fingerprint — контрольная метка, а не архив исходного промпта.

## Безопасная проверка через GitHub Actions

Чтобы проверить ключи без отправки их в чат, добавьте их в **GitHub → Settings → Secrets and variables → Actions**. Приложение поддерживает следующие канонические имена:

| Провайдер | Рекомендуемые Secrets |
|---|---|
| Gemini | `GEMINI_API_KEY` |
| Groq | `GROQ_API_KEY` |
| xAI / Grok | `XAI_API_KEY` |
| Pollinations (для server smoke test нужен секретный `sk_…`, не App Key `pk_…`) | `POLLINATIONS_API_KEY` |
| OpenRouter | `OPENROUTER_API_KEY` |
| NVIDIA NIM | `NVIDIA_API_KEY` |
| Hugging Face | `HF_TOKEN` |
| Cloudflare | `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` |

### Проверить все ключи одним запуском

Откройте **Actions → Provider smoke test — all configured secrets → Run workflow**. Workflow проверит каждый провайдер, для которого найдётся подходящий Actions Secret; если ключа нет, этот провайдер будет помечен **SKIPPED**, а не ошибкой. Для каждого настроенного сервиса выполняется один короткий реальный запрос к указанной модели. Результат включает провайдер, модель, HTTP-статус, время ответа и безопасную причину ошибки. Любой неудачный реальный запрос приведёт к failed workflow, при этом остальные провайдеры всё равно будут проверены.

Workflow принимает и распространённые короткие названия секретов: Gemini — `GEMINI`, `GOOGLE_GEMINI`, `GEMINI_KEY`; Groq — `GROQ`, `GROQ_KEY`; xAI — `XAI`, `GROK`, `GROK_API_KEY`, `GROK_KEY`; Pollinations — `POLLINATIONS`, `POLLINATIONS_KEY`; OpenRouter — `OPENROUTER`, `OPENROUTER_KEY`; NVIDIA — `NVIDIA`, `NVIDIA_NIM_API_KEY`; Hugging Face — `HUGGINGFACE`, `HUGGING_FACE`, `HF`; Cloudflare — `CLOUDFLARE`, `CLOUDFLARE_API_KEY`, `CLOUDFLARE_TOKEN` (и `CF_ACCOUNT_ID` / `CF_ID` для Account ID).

Pollinations App Key с префиксом `pk_` не является server access token и будет помечен как **SKIPPED**, а не отправлен в API. Для live smoke-test нужен отдельный секретный токен `sk_`; браузерное подключение приложения по-прежнему использует App Key + OAuth PKCE.

**Учтите стоимость:** запросы небольшие, но провайдер может списать токены/квоту; Pollinations расходует Pollen. Не используйте этот workflow как непрерывный мониторинг. Значения секретов не выводятся в журнал.

Actions Secrets доступны workflow на стороне GitHub, но **не становятся доступными статическому сайту GitHub Pages или GitHub-коннектору ChatGPT**. Каталог моделей в браузере всё равно требует ключ, введённый в настройках приложения (исключение — публичный каталог Pollinations).

## Что означает статус лампы и «Оффлайн»

- **Серая** лампа — ключ не введён.
- **Янтарная** — ключ задан, но проверка ещё не прошла.
- **Зелёная** — короткий реальный запрос к выбранной модели успешно ответил.
- **Красная** — проверка завершилась ошибкой. Точный HTTP-код виден рядом с индикатором.
- Кнопка **«Оффлайн»** выключает веб-поиск и внешние источники. Она не отключает интернет для облачной модели: любой удалённый API всё равно требует сеть.

Большинство обычных ключей приложения хранится в `localStorage` текущего браузера; это не серверное хранилище секретов. Любой скрипт, работающий в контексте страницы, теоретически может их прочитать. Для более сильной защиты нужен серверный proxy/backend. Pollinations OAuth access token хранится только в `sessionStorage` текущей вкладки и истекает.
